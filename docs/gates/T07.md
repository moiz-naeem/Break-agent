- **Deviations from PRD/ticket (and why):**
  - `task.toml` uses `schema_version = "1.4"`, not `version = "1.0"`. That is the key Harbor 0.26.0 validated
    in the spike, and the ticket says to use the spike's keys. It also adds `build_timeout_sec = 900`.
  - The sim image runs `python -m railway.server ...` instead of `railway-sim`. The image copies `railway/`
    rather than pip-installing the project, so there is no console script.
  - Both images are `python:3.11-slim`. The main image pins the full `uv.lock` dependency closure of
    pydantic, mcp and httpx inline in its Dockerfile, so the layout of §2.3 is unchanged. The closure uses
    the Linux/CPython 3.11 markers, so `pywin32` is dropped.
  - `verify.py` has extra flags:
    - `--tests-dir`: defaults to its own folder;
    - `--agent-logs-dir`: defaults to `/logs/agent`;
    - `--probe`.
  - A 4xx from `/episode_log` is not retried. It prints `INFRA: episode_log refused (HTTP 403)`.
  - The verifier deletes any existing `reward.txt` and `reward.json` before it starts. An agent could
    otherwise pre-write a reward that survives an infra exit, and Harbor prefers `reward.json`.
  - The verifier also checks `final_tick`, `scenario_id`, `closed` and the entry shapes, and that
    `norm.json` matches the scenario hash and the rules version.
  - The probe `solve.sh` runs the isolation checks and then the oracle, so the probe trial also scores 1.0.
    The `import railway` check runs from `/` with `PYTHONPATH` unset, so the vendored `/solution` code doesn't
    count as importable.
  - The export command is `python -m railway.harbor.export` (`main()`). Wiring it into `gen export` belongs in
    T04's `railway/gen/cli.py`.
- **MCP startup-failure rule (spike risk 2):**
  - **Trial error:** the episode log has **zero** budgeted tool calls (entries refused with
    `R-SHIFT-ENDED` don't count) **and** a line under `/logs/agent` names our server and reports a failure.
    - A line names our server if it contains `key=railway` or `server=railway`, or both `mcp` and
      `railway`.
    - A failure is a whole-word match of unavailable, failed, failure, error, refused, timeout, timed out
      or unreachable.
    - The verifier then prints `INFRA: agent started without MCP tools ...`, exits 1 and writes no reward.
  - **Scored normally:**
    - zero calls with no such line (no agent logs, as with `nop`; a healthy MCP line; the probe's
      `No module named 'railway'`; another server's failure; the prompt) → 0;
    - any episode with ≥ 1 call, whatever the agent log says.
