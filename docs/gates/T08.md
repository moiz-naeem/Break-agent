## Deviations from PRD/ticket (and why)

- **Not built here (owned by other tickets' files):**
  - `Session.peek` and `disabled=` support in `railway/tools/session.py` (T05 file).
  - `Greedy.decide` in `railway/policies/greedy.py` (T05 file).
  - The `railway-eval` console script in `pyproject.toml`.
  - `railway/tools/schemas.py` **was** created here: T05's scope doesn't list it and T08's does.
- **Interface assumptions** (check them when T04–T07 land):
  - `railway.tools.session.REGISTRY` maps name → (args model, handler, …). Tool descriptions are the first line of the handler docstring (else the args model's), so the MCP server's docstrings should come from the same place.
  - A Session may expose `.registry`.
  - `Session(scenario, disabled=..., diagnostics=...)`.
  - `session.final` / `close()` return `{tick, cost, counts}`. Unfinished trains are counted from `peek("status", {})` after close, unless `counts["unfinished"]` exists.
  - `railway.harbor.verify.reward_from(c_greedy, c_ref, c_agent)` returns a mapping, object or tuple carrying `reward` and `score_unclipped`.
  - The T07 instruction template lives at `railway/harbor/templates/instruction.md` with a `{TOOL_BUDGET}` placeholder.
  - `railway.gen.generator.generate`, `railway.gen.presets.PRESETS[preset]` and `railway.ref.seed_filter.accepted_seeds` return items with `seed, scenario_hash, c_greedy, c_ref`.
  - Harbor trials map to tasks through a task path in `config.json`, or the `<task>__<id>` dir prefix. Tokens are `n_input_tokens` / `n_output_tokens` if `result.json` has them, else null.
- **Choices made:**
  - The system message is `instruction + "\n\n" + suffix`.
  - Tool-call ids in the prompt are renumbered `call_<n>`, so prompts don't depend on the provider.
  - Empty `arguments` (`""`) is treated as `{}`.
  - The transcript has one line per model reply, prose replies included.
  - The Harbor harness re-runs the whole dataset when any pair is missing; Harbor has no per-pair filter. It appends only the missing pairs.
  - `planned` in `summarize` is the number of distinct (scenario_id, rep) pairs in the file.
