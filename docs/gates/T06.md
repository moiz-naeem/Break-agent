- **Date / people:** 2026-11-14, Claude (Opus 5.5) for the user.
- **Origin:** the first T06 implementation was written in a separate checkout on a T01/T02-only base. It imported
  T05 modules that didn't exist yet. It was ported here after T05 was finished, then fixed as below.

## Deviations from the ticket (and why)

- **Rollout base policy is exactly T05 greedy** (`ref/candidates.py:greedy_choice`), not "safe greedy" (§2.3).
  With the ticket's base policy the reference lost to greedy on 3 of the first 10 T1 dev seeds (T06-09 needs at
  most 1 loss). A rollout policy is only guaranteed to be no worse than its base policy when the base policy is
  the one it should beat. The reference's *own* grants still pass the deadlock-safety filter, and rollouts that
  gridlock still score +10,000.
- **Greedy's own move is always among the candidates** (§2.2 step 5 keeps only the 5 farthest destinations, which
  often drops greedy's nearest-loop hop). It is appended before `WAIT`.
- **Effect on the first 10 T1 dev candidates:**
  - before: reference ≤ greedy on 7 of 10;
  - after: reference ≤ greedy on 10 of 10, total cost 0.33 × greedy, no gridlocks, no unfinished trains.

  On 4 T2 dev seeds the ratio is 0.26–0.66, at 19–36 s per episode.
- **Offline search rewritten.** The ported version stopped after `shift_ticks + 1` beam expansions, but each
  decision point takes several expansions. It could therefore report a partial plan's *estimate* as a cost.
  Every kept plan now runs to the shift end.
- **Seed filter** uses the runner's real count of unfinished trains (the port guessed it from the unfinished
  cost). Accepted lists are scanned in parallel batches but taken strictly in seed order, so the file doesn't
  depend on the worker count.
- **Generator / presets / `TOOL_BUDGET`:** recalibrated with the user's approval; see `docs/gates/T05.md`.
- **Freight unfinished charge (rules change, user-approved, `RULES_VERSION` 0.1 -> 0.2-provisional).** The first
  full T1 scan accepted only 20 of 137 candidates (15%; T06-19 needs 30%): `HoldFreight` (the reference with all
  freight dropped) beat greedy on 111 of them. It strands 2 freight trains for about 530, while greedy loses
  thousands untangling them. DESIGN §6.5 says unfinished charges should outweigh that. Now each unfinished
  freight train adds `UNFINISHED_FREIGHT_EXTRA` (1000) x `shift_ticks` / `UNFINISHED_FREIGHT_SHIFT` (240): +1000 on
  T1, +3000 on T2. A flat +1000 was tried first and still left T2 at 3/20 (HoldFreight undercut greedy by
  1,000-23,000 on T2's 720-tick shift). Manual, PRD (constants, cost table, worked example) and every pinned
  cost (T02-26/32, T03-04, T05-03/04/19/19b/25/27, T08 do-nothing on mini3) are updated: each moved by exactly
  the new charge for F21, the one unfinished freight train in `mini3`.
- **`generator_version` no longer hashes `railway/gen/cli.py`**: adding `gen export` (T07) would otherwise have
  invalidated every accepted list although no scenario changed.
